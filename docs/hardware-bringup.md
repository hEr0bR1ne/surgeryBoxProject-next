## 灯指令

USB 串口使用 115200 波特率，每条指令以换行结束；也支持 UDP。

| 指令 | 作用 |
| --- | --- |
| `LIGHT:ON` | 开灯，回复 LIGHT:ON |
| `LIGHT:OFF` | 关灯，回复 LIGHT:OFF |
| `LIGHT?` | 查询最后设置的逻辑状态；不是灯实际发光检测 |

灯指令可在固件等待 OK、OK1、OK2 或继续拉出时处理，不终止原训练等待。桌面串口监听器可接收 LIGHT: 状态；实体模式提前建立既有串口/UDP 连接，不为开灯发送 Start 或电机指令。指令等待就绪并重试，10 秒未确认时提示失败。退出时在关闭通信前发送 OFF；如果连接已断，软件无法保证实体灯熄灭，会记录错误。

## 联调顺序

确认 AIN2 接线和 MOS 触发极性 → 选择正确串口并编译上传 → 检查握手 → 单独确认灯亮灭 → 检查编码器 → 在机械允许的条件下短时测试电机方向与停止 → 最后运行完整训练流程。

已在 COM4 / 115200 验证 HELLO_PC 握手、LIGHT:ON/OFF、LIGHT?，以及 PINS? 返回的 D3 电平依次为 0 → 1 → 0；测试后灯逻辑状态为 OFF。没有发送电机动作指令，未验证 MOS 功率输出或灯实际发光，也未验证编码器运动。

可复用测试命令：`python tools/check_blood_light.py --port COM4`。此命令会短暂切换灯控制输出，最后关闭灯；不会控制电机。

## 上位机运行与行为

默认 ESP8266 串口已从 COM6 改为用户确认的 COM4，可用 `SURGERYBOX_SERIAL_PORT` 覆盖。IMU 仍走独立 COM3。`SURGERYBOX_BLOOD_LIGHT` 默认为 1，设为 0 可恢复 PNG 模拟血迹且不为灯额外打开设备连接。

实体灯替换三个血迹 PNG 的显示，保留摄像头、棉球提示、手势判定和训练进度。当前只有开关灯：进入擦血阶段点亮，完成整个擦血阶段关闭，不模拟三层图片逐渐淡出。体位暂停期间保留当前灯状态，退出页面时关闭。

相机训练原本有约 8 秒自动完成擦拭的回退逻辑，本次保留；因此灯熄灭不一定意味着检测到实际擦拭动作。纯 MCU 模式默认关闭摄像头并跳过阶段 1–3.5，仍不触发此灯光阶段。

上位机改动验证：17 项测试通过（包括真实 Qt 定时器接入和两份实际阶段方法的无设备测试），应用 Python 源码语法检查通过，两份训练模块导入成功。未跑完整相机/IMU训练：本机已找到的 surgeryBox Python 环境没有 MediaPipe。此次上位机集成未再上传固件或执行电机动作；之前已上传的灯控制固件兼容这些指令。
